# who/coordination/: how to contribute

**Questions, errors and other perspectives** are welcome as issues on this repository. An error report is most useful
with the file and line, what it says, and the source that says otherwise.

**A change** comes as a pull request that keeps the project's rules (the root `CLAUDE.md`, *Rules to keep*): every new
value with its source, identifier, version or retrieval date, and method; every new check with what would count against
it, fixed beforehand, and a planted fault it catches. A change to a release's data comes with the code that produced it
and its checks, so that it can be re-run.

**How a change reaches a release.** ChannelScope is developed in a private aDNA vault, as aDNA itself is, and published
here as reviewed, tagged releases. The maintainer reads pull requests; none is promised a merge or a date. An accepted
change is carried into the development vault, checked there with the rest, and published in a later tagged release,
which credits its contributor. A release's history is not rewritten after it is published.

**Sessions** stay in the contributor's own copy (`how/sessions/AGENTS.md`); a pull request carries the change and its
evidence, not the session.
